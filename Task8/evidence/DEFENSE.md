# Краткие ответы на защите

**Почему три разных БД?** Чтобы сервисы не зависели от чужой схемы данных. Единственный межсервисный способ получения данных — HTTP API либо асинхронные события.

**Зачем API Gateway, если есть Traefik?** Traefik отвечает за инфраструктурное направление входящего трафика к Gateway; Gateway выполняет логическую маршрутизацию /api/* и создает сквозной X-Request-ID.

**Почему заказ не создает доставку напрямую?** Асинхронность уменьшает синхронную связанность. Order Service фиксирует заказ и публикует OrderCreated, Delivery Service независимо обрабатывает сообщение.

**Что произойдет при двукратной доставке сообщения?** `processed_events(event_id)` вставляется с `ON CONFLICT DO NOTHING` в одной транзакции с записью `deliveries`. Кроме того, `UNIQUE(order_id)` запрещает две доставки одного заказа.

**Зачем Outbox?** Чтобы сохранение заказа и запись намерения отправить событие были в одной транзакции. Если брокер временно недоступен, запись останется в outbox и публикатор повторит отправку.

**Почему доставка может появиться позже заказа?** Eventual consistency: обработка события независима и не совпадает по времени с HTTP-ответом `201 Created`.

**Что делают timeout/retry/CircuitBreaker?** Timeout ограничивает время одной попытки, Retry делает только 2 попытки подходящих сетевых ошибок, Circuit Breaker временно запрещает вызовы постоянно падающего Supplier Service.

**Как работает SSE?** HTTP-клиент открывает долго живущее GET-соединение `Accept: text/event-stream`. Spring WebFlux возвращает `Flux<ServerSentEvent>`. Значения CREATED/ACCEPTED/IN_TRANSIT/DELIVERED поступают без повторных HTTP GET. Это однонаправленный поток.

**Есть ли WebFlux на всех сервисах?** Нет, нужен минимум один: Delivery Service. Order и Supplier используют привычные блокирующие Spring MVC/JDBC. В Delivery Service база через R2DBC, а AMQP listener работает отдельным worker.

**Как отслеживать один запрос?** Gateway добавляет `X-Request-ID`, Order передает его HTTP Supplier, а затем в поле `requestId` события RabbitMQ. Логи всех сервисов содержат один ID.

**Есть ли недостатки?** Пример учебный: нет атомарного резерва товаров и аутентификации, SSE не распределенный по нескольким инстансам, outbox поддерживает семантику at-least-once, требуется защита служебного replay endpoint.
